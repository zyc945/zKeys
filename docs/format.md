# 文件格式与兼容约定

[返回 README](../README.md) · [完整命令](commands.md) · [备份与迁移](migration.md)

本工具使用固定路径 `~/.config/z-keystore/vault.json`，一个文件保存整库。以下描述对应现有 v1 格式；工具版本与文件格式版本相互独立，新增命令不改变 v1 格式。

## 外层密文

文件为 UTF-8 JSON 对象，恰有四个字段：

| 字段 | 类型与含义 |
| --- | --- |
| `version` | JSON 整数 `1` |
| `salt` | 16 字节随机 salt 的标准 Base64 字符串 |
| `nonce` | 12 字节随机 nonce 的标准 Base64 字符串 |
| `ciphertext` | AES-GCM 密文及末尾 16 字节认证标签的标准 Base64 字符串 |

Base64 使用标准字母表和所需的 `=` 填充，不插入换行。JSON 字段顺序和空白不参与认证，无需在不同设备间重新序列化或转换文件。

加密和解密步骤：

1. 将主密码按 UTF-8 编码，不做 Unicode 规范化或额外裁剪；交互输入的结束换行不属于密码。没有硬性长度限制，已有空密码或短密码仍兼容。
2. 使用 Scrypt，`N=32768`、`r=8`、`p=1`、输出长度 `32` 字节，以密码字节和 `salt` 派生 AES-256 密钥。
3. 明文为 UTF-8 JSON 对象，名称和字符串值一起加密。名称必须满足 `^[A-Za-z0-9][A-Za-z0-9_.:/-]{0,127}$`；值不得包含 NUL。普通写入命令要求值非空，格式读取仍兼容空字符串。
4. 使用 AES-256-GCM、12 字节 `nonce` 和固定 AAD 字节串加密；AAD 为 ASCII/UTF-8：`z-keystore:v1:scrypt-32768-8-1:aes-256-gcm`。
5. 将密文与 GCM 标签连接后编码到 `ciphertext`。每次保存整库都会重新生成 salt 和 nonce。

库不包含密码、密码恢复信息或设备绑定材料。密码错误和认证失败统一报告无法解锁；仅凭该错误无法区分错误密码、损坏或篡改。没有防回滚保护；旧备份可用其对应的旧密码解锁。

## 文件与写入约定

数据目录必须为当前用户所有的真实目录，权限恰为 `700`。`vault.json` 和本地 `.lock` 必须为当前用户所有、权限恰为 `600` 的普通文件，不接受符号链接或多重硬链接。

所有库操作沿用 `.lock` 的独占文件锁。保存先在同目录创建 `.vault-*` 临时文件，写入并同步后原子替换 `vault.json`，再同步目录。不要手动改写密文或跨设备复制锁文件；复制完整 `vault.json` 前等待写入命令结束。已运行的程序环境和 Zellij 会话不包含在文件中。

## SSH 快照

SSH 快照位于普通条目 `ssh/NAME` 的字符串值内，因此外层 v1 格式不变。该字符串本身为 JSON，结构如下：

| 字段 | 内容 |
| --- | --- |
| `type` | 固定字符串 `zkeys-ssh` |
| `version` | 整数 `1`，SSH 快照自身的格式版本 |
| `hosts` | 主机数组；每项含 `name` 和有序 `options`，每个选项含 `name` 和字符串数组 `args` |
| `files` | 文件数组；每项含生成的 `id`（如 `f0001`）、`kind` 和标准 Base64 编码的原始字节 `data` |

`kind` 为 `private`、`public`、`certificate` 或 `known_hosts`。文件引用使用生成的 ID，导出时重新映射为目标路径；不使用原机器的绝对路径作为落盘目标。带口令的 SSH 私钥保留原始加密字节，原口令不会被移除或另存。

SSH 解码拒绝未知或重复字段，并校验选项、文件引用、类型和跳板依赖。完整静态配置支持范围见 [SSH 命令](commands.md#第一版支持范围与限制)。不要用 `zkey get ssh/NAME` 检查格式，它会输出包含私钥的整个 JSON 字符串。

## 恢复所需信息与维护边界

恢复需要完整的 `vault.json`、该文件对应的主密码，以及支持 v1 的工具。算法参数与 AAD 固定在实现中，没有另存进文件；建议同时记录 `zkey --version`、`zwork --version`，需要长期独立恢复时另存对应版本源码或发布包。SSH 私钥原有的独立口令也应自行保管。恢复操作见[迁移文档](migration.md)。

Go 是唯一新增功能实现。`z_keystore.py` 和 `zwork.py` 保留为格式参照与兼容验证入口，不追求命令功能同步，不在本轮删除已有参考代码或测试。Python 需要 `requirements.txt` 中的依赖；不参与 Go 二进制运行，也不支持新增的 `import-env`、`export`、`import`、`ssh`、`delete` 和 `--version`。

固定兼容向量位于源码仓库中的 `tests/fixtures/keystore-v1.json`，Go/Python 各自读取既有密文并核对预期条目，防止读写实现一起改变而掩盖格式破坏。向量仅含公开虚拟数据，固定 salt/nonce 不用于真实库。

Go 与 Python 均能直接读写 v1：两者 JSON 序列化的空白和转义可以不同；解密后的条目内容应一致。SSH JSON 对 Python 仍是普通字符串，可随整库读写保存；只有 Go 提供 SSH 导入导出命令。兼容测试和平台实际验证边界见[验证说明](commands.md#验证与-python-兼容性)。
